# VETKIND AI DEVELOPMENT RULES

RULE 1: Never rewrite working functionality unnecessarily.
RULE 2: Before changing architecture, inspect the existing code.
RULE 3: Use reusable components.
RULE 4: Do not duplicate UI code.
RULE 5: Do not hard-code product data into components.
RULE 6: Use TypeScript strictly.
RULE 7: Do not use `any` unless absolutely unavoidable.
RULE 8: Keep secrets in environment variables.
RULE 9: Never invent company claims, certifications, scientific evidence, clinical results or product specifications.
RULE 10: When information is missing, use clearly marked placeholders.
RULE 11: Every new feature must work on: desktop, tablet, mobile.
RULE 12: After every development phase:
  1. Run lint
  2. Run type checking
  3. Run production build
  4. Test major routes
  5. Fix errors
  6. Report completed functionality
RULE 13: Do not proceed to the next major phase if the current phase has build errors.
RULE 14: Prefer simple reliable architecture over unnecessary complexity.
RULE 15: SEO is mandatory.
RULE 16: Accessibility is mandatory.
RULE 17: Performance matters.
RULE 18: Never copy copyrighted content or branding from reference websites.
RULE 19: Reference websites may influence UX architecture but VetKind must have its own branding, copy, imagery, product information, colors, visual identity.
RULE 20: Before making major changes, explain: WHAT, WHY, IMPACT, FILES AFFECTED, then implement.
